# aipassport v0.2.0：三场景 + 分段录入协议设计

> 状态：设计定稿（2026-09-08），companion 与固件按此契约实现。
> 前置：v0.1.1 汉化固件正常（bitmap_format=0 未压缩字库已生效）。

## 一、产品流程（用户确认版）

```
【场景选择】(设备 HOME/首启)
  同事(work_wechat) / 领导客户(report_boss) / 对AI(agent_prompt)
        │ 选中场景 → READY（顶部显示当前场景标签）
        ▼
【分段录入】READY
  按音量+说话 → 松手 → 本段转写 → 设备屏显示「第N段预览」
  ├─ 段数<3：可再按音量+ 继续录（内容追加）
  └─ 按 OK：结束录入（≤3 段）
        ▼
【自动合并整理】(relay 收"结束录入"信号)
  多段文本合并 → DeepSeek 按场景 preset 综合整理 → 整理稿下行设备屏
        ▼
【确认注入】设备屏显示整理稿
  └─ 按 OK：确认 → 注入当前输入框（对AI 场景同样注入输入框）
```

- 分段上限 3 段；单段也可（录 1 段直接 OK）。
- 段预览与最终整理稿都在**设备屏幕**上显示（用户逐段/整体可读）。

## 二、下行协议（Mac relay → 设备，CTRL 通道 JSON 行）

| type | 字段 | 触发 | 设备行为 |
|---|---|---|---|
| `scene.set` | `scene: "work_wechat"\|"report_boss"\|"agent_prompt"` | 用户选场景 | 存当前场景并显示在 READY |
| `transcript` | `text, final`（已有） | 每段 ASR 中间结果 | 本段预览（final:false 光标感） |
| `segment.ready` | `index: 1..3, text` | 本段转写**定稿**后 | 显示「第 N/3 段已录 ✓ 预览文字」+ 按键提示 |
| `merge.result` | `text` | 多段合并整理完成 | 显示整理稿全文 + 「OK=发送 其他=放弃」 |
| `agent.status` | `state, message`（已有） | done | 回 READY（单段兼容路径） |

## 三、上行协议（设备 → relay，EVENT 通道 JSON 行）

| event | 字段 | 触发 | relay 行为 |
|---|---|---|---|
| `voice.start/end` | audio（已有） | 每段 PTT | 段转写，定稿后下行 `segment.ready`，**不注入** |
| `scene.select` | `scene: "work_wechat"\|"report_boss"\|"agent_prompt"` | 用户确认场景 | 切换 refine_preset + 下行 `scene.set` 确认 |
| `recording.done` | （新） | 用户按 OK 结束录入 | 合并 buffer 全部段 → refine(综合) → 下行 `merge.result` |
| `inject.confirm` | `ok: true/false` | 整理稿页按 OK / 放弃 | ok=true → 注入整理稿；false → 丢弃。均下行 `agent.status done` |

## 四、companion 端改动清单

1. `refine_deepseek.py`：
   - 新增 preset `agent_prompt`（对 AI/vibe 场景）✅ 已做
   - `_build_messages` 识别多段标记 `◆第N段◆` → 综合整理指令 + 200 字上限 ✅ 已做
2. `relay.py`（本次实现）：
   - `__init__` 新增状态：`self._scene`（默认 work_wechat）、`self._seg_buffer=[]`、`self._merge_mode=False`
   - 场景切换：`scene.select` 事件 → `cfg["refine_preset"]=scene` + 下行 `scene.set`
   - 多段收集：voice.end 定稿后 → 存 `_seg_buffer` + 下行 `segment.ready`（**不再直接注入**）
   - 结束录入：`recording.done` → 拼多段文本（`◆第N段◆` 分隔）→ refine → 下行 `merge.result`
   - 确认注入：`inject.confirm ok=true` → `_inject(合并稿)`；ok=false → 丢弃
   - 兼容：单段无 buffer 时 `recording.done` 直接 refine 该段
3. `config.local.json`：`refine_preset` 保留默认（设备场景选择会覆盖运行态），`voice_min_sec` 不变

## 五、固件端改动清单

1. `app_types.h`：
   - 状态新增：`APP_ST_SCENE_SELECT`（场景选择）、`APP_ST_SEG_WAIT`（段间等待，可续录/结束）、`APP_ST_MERGE_REVIEW`（合并稿确认）
   - 事件新增：`APP_EV_SCENE_SET`（下行 scene.set）、`APP_EV_SEGMENT_READY`、`APP_EV_MERGE_RESULT`
   - 上行事件枚举/协议串：`scene.select`、`recording.done`、`inject.confirm`
2. `app_state.c`：
   - HOME/READY 按键：OK 进入场景选择；UP 长按=说话（READY）
   - SCENE_SELECT：音量+/- 切换 3 场景，OK 选中（上行 scene.select）
   - 录音定稿后：进 SEG_WAIT（显示段预览），UP 再录、OK=recording.done
   - MERGE_REVIEW：OK=inject.confirm ok:true / UP=ok:false
3. `app_ui.c`：场景选择页（3 行高亮）、SEG_WAIT 页（第 N 段预览+提示）、MERGE_REVIEW 页（整理稿+提示）
4. `app_protocol.c`：下行 scene.set/segment.ready/merge.result 解析；上行 scene.select/recording.done/inject.confirm 序列化

## 六、兼容与回退

- 单段录音流程等价：录 1 段 → OK → 整理 → 确认 → 注入（多一步确认，符合用户选择）
- `--no-approval` 仍然可用（跳过的是旧的 agent 审批演示，与分段确认无关）
- 旧协议文本（未实现分段前）下：relay 收到无 `recording.done` 时按超时自动合并兜底（可选）
