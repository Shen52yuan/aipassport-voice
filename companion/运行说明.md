# aipassport 运行说明（本地 whisper + DeepSeek 改造版）

## 0. 先搞清楚：软件跑在电脑，不烧进芯片

- **ESP32 设备**：只负责录音 + 蓝牙把音频流发出来，跑的是 FoloToy 出厂固件（设备买来就烧好，无需也不能重刷我们的代码）。
- **本仓库 `companion/`**：跑在 Mac 上的中转程序（`relay.py`），负责 本地 whisper 转写 → DeepSeek 整理 → 注入当前输入框。
- 官方玩法页 `ai-passport.folotoy.cn/plays/45` 的安装 = 下载桌面客户端(电脑端) + 蓝牙/有线连设备 +「安装」按钮把 agent 玩法配置推到设备。软件本身不在芯片上。

## 0.5 ⚠️ 出厂固件 ≠ companion 固件（最关键的认知）

官方《第一次使用》文档原文：
> 「AI Passport **出厂已经内置身份卡玩法，不需要连接电脑或安装其他内容**。」
> 「开机：**按住电源键 0.5 秒**，屏幕点亮并进入主界面。」
> 「打开**手机**蓝牙和官方 App（微信小程序），在『附近的设备』中选择你的 AI Passport。」

**含义**：设备出厂烧的是「**身份卡玩法**」固件，面向**手机 App** 通过 BLE 连接。它**不是** `folo-ai-passport-voice` 仓库里的设备端固件，因此：

| relay.py 需要的能力 | 出厂身份卡固件 | companion 设备端固件（`main/`） |
|---|---|---|
| BLE GATT `0xA2B0` 音频/事件服务 | ❌ 无 | ✅ 有 |
| `usb_link` USB 通道（ping/pong） | ❌ 无 | ✅ 有 |
| 控制台命令面（`st`/`mode`/`help`） | ❌ 无 | ✅ 有 |
| 广播名 `AI Passport` | ❌ 不广播 | ✅ 广播 |

**所以：拿到新设备直接跑 `relay.py` 必然报「未发现设备」，不是故障，是固件不对。**

### 怎么判断当前跑的是哪个固件（四步，无需拆机）
1. 发 esptool SYNC 帧有应答 → 在 ROM 下载模式（无固件）
2. 串口发 `st`/`help` 有回显 → companion 固件在跑
3. `channel=usb` 跑 relay.py 握手成功 → companion 固件且处于 USB 模式
4. BLE 扫到 `AI Passport` → companion 固件且 BLE 广播中

> 四项全灭 = 正在跑出厂身份卡固件（或设备未开机）。

### 让设备为我们工作：两条路
- **A. 装官方「语音」玩法**：在 `ai-passport.folotoy.cn/plays/` 找到语音/伴生类玩法，点「安装」推到设备。若该玩法即 companion 固件，装完就能用 `relay.py`。
- **B. 自行编译设备端固件**：上游**没有预编译 release**（releases 为空、`dist/` 为空），只有 `main/` + `components/` 源码（ESP-IDF 5.5 + LVGL 9.5）。需装 ESP-IDF 编译出 .bin，再用 Web Flasher（§4.5）写入。

## 0.6 实测进展（2026-09-07 下午，结论已定案）

### ✅ 设备的 BLE 是健康的，只是广播名不是 "AI Passport"
扫到一台名为 **`4c11ae326718`** 的设备（地址 UUID `03C18CD7-…`）——正是本机 SN（MAC 去冒号）。
说明 TRAE 默认固件**确实在广播 BLE**，只是广播名 = SN，所以按 "AI Passport" 永远扫不到。

> 注意：`at+config=?` 里 `name=TraeWork`，但**实际广播名是 SN**，别按 TraeWork 找。
> 另：`standby_time=300`，5 分钟无操作进待机会**停止广播**，扫描前按一下按键唤醒。

### ❌ 但是：广播名对上 ≠ 能用
`relay.py` 只认 GATT 服务 `0000A2B0-…`（下含 A2B1 CTRL / A2B2 EVENT / A2B3 AUDIO）。
TRAE 默认固件**没有这套服务**，就算强行 `--device` 指定地址，也会因找不到服务而失败。

终局判定（你在真机终端跑一次即可定案）：
```bash
python probe_gatt.py 03C18CD7-85B8-52D7-F9CA-D375531D5474
```
- 输出「✅ 设备提供完整 0xA2B0 音频服务」→ 固件可用，直接 `python relay.py --device <UUID>`
- 输出「❌ 未发现 0xA2B0」→ 当前固件不可用，必须换固件

### 🔍 有没有现成固件可刷？→ **没有**
| 来源 | 结果 |
|---|---|
| 上游 `folo-ai-passport-voice` releases / `dist/` | 空 |
| 官方 `FoloToy/ai-passport` releases | 空 |
| 官方固件库 `FoloToy/folotoy-bin` | 只有 README |
| 上游全部 fork（1 个） | 零 .bin release |
| 社区 `JollySun/folo-ai-passport-niulai` | 有 `full.bin`（SHA256 校验一致、确为 ESP32-C3），**但它是「牛来/Mama」玩具玩法固件**（`UP=Niu Lai, DOWN=Mama, hold UP/DOWN=record`），**不含 0xA2B0**，刷了也没用 |

**结论：配套固件只能自行编译（路径 B）。**

### 🚀 不等固件：麦克风版今天就能用整条链路
`mic_relay.py` 绕开硬件，用 Mac 自带麦克风复用同一套「本地 whisper → DeepSeek 整理 → 注入光标」逻辑：

```bash
python mic_relay.py                 # 回车开始录音，再回车结束
python mic_relay.py --seconds 8     # 固定录 8 秒
python mic_relay.py --no-inject     # 只打印不注入（安全试跑）
python mic_relay.py --wav a.wav     # 喂现成 16k 单声道 wav
```
已实测通过（英文样本）：ASR 出原文 → DeepSeek 出成稿 → 注入。

## 1.5 本机设备信息（2026-09-07 esptool.js 实测确认）

```
Chip:       ESP32-C3 (QFN32) revision v1.1
Features:   Wi-Fi, BLE, Embedded Flash 8MB (XMC)
Crystal:    40MHz
MAC(base):  4c:11:ae:32:67:18
USB:        VendorID 0x303a / ProductID 0x1001（USB JTAG/serial debug unit）
Flash ID:   174020
状态:       [device] 设备已就绪
```

> 交叉验证：`ai-passport.folotoy.cn/trae/?s=4c11ae326718` 里 `s=` 就是 MAC 去冒号，与本台一致。

### ⚠️ macOS 上别用这个 MAC 连 BLE（重点）

bleak 在 macOS 返回的是 CoreBluetooth **UUID**（形如 `XXXXXXXX-XXXX-XXXX-XXXX-XXXXXXXXXXXX`），不是 MAC：
- `BleakClient("4c:11:ae:32:67:18")` **会连不上**（macOS 不认 MAC）。
- esptool 给的 `...:18` 是 base/WiFi STA MAC；ESP32 的 BLE MAC 通常是 base+2（`...:1a`），但 macOS 压根用不到 MAC。

✅ **推荐做法**：`--device` 不传，让 `relay.py` 按广播名 `"AI Passport"` 扫（macOS 最稳）。
✅ **想跳过扫描**：先在真机终端取一次 UUID，再传 UUID（见下）。

## 2. 真机运行（必须在你自己的 Mac 终端，不在 WorkBuddy 沙箱）

```bash
cd /Users/Zhuanz/WorkBuddy/Aipassport/folo-ai-passport-voice/companion

/Users/Zhuanz/.workbuddy/binaries/python/envs/default/bin/python relay.py
```

首次运行需开两个 macOS 授权（系统设置 → 隐私与安全性）：
- **蓝牙**：让 Python 能扫到 "AI Passport" 设备（沙箱就是卡在这）。
- **辅助功能**：注入剪贴板 + Cmd+V 必需，否则整理稿进不了输入框。

预期输出（连上后）：
```
[relay] 连接 <设备地址> ...
[relay] 已连接, 订阅 EVENT/AUDIO
[relay] 等待语音(PTT 按住说话; Ctrl+C 退出)
```
然后**按住设备音量+说话，松手**即把整理好的文字注入当前光标处。

常用参数：
- `--dry-run` / `--no-inject`：只转写不注入（调试用，不会往窗口塞字）。
- `--device <标识>`：指定设备，跳过扫描。**macOS 必须传 CoreBluetooth UUID，不能传 MAC**（见 §1.5）。不传则按名扫 `"AI Passport"`，最稳。

取 UUID（真机终端跑一次，需蓝牙授权）：
```bash
cd /Users/Zhuanz/WorkBuddy/Aipassport/folo-ai-passport-voice/companion
/Users/Zhuanz/.workbuddy/binaries/python/envs/default/bin/python -c "
import asyncio
from bleak import BleakScanner
async def m():
    d = await BleakScanner.find_device_by_name('AI Passport', timeout=15)
    print('BLE UUID:', d.address if d else '未找到(确认设备开机/蓝牙授权)')
asyncio.run(m())
"
```
拿到 UUID 后即可 `relay.py --device <UUID>` 固定连这台。
- `--no-approval`：关闭审批演示。
- `--timeout 60`：等待最终结果/审批的超时秒数。

## 4.5 固件刷写（Web Flasher，需要时才用）

官方页：`https://ai-passport.folotoy.cn/tools/web-flasher/`
这是 **ESP32-C3 芯片固件刷写器（浏览器 WebSerial 方式）**，刷的是芯片里的 FoloToy 固件，**不是我们的 `companion/` 软件**（软件永远跑在 Mac 上）。

### 什么时候才需要刷
- ✅ **需要刷**：设备空白/变砖、固件损坏、或你想升级到最新官方固件。
- ⏭️ **不用刷**：你的设备已开机（USB 接上就出了 `/dev/cu.usbmodem*`，说明固件在跑）。只想用本 `relay.py` 做"说话→整理→注入"，**直接跑 relay.py 即可**，无需刷机。

### 刷机前提（关键）
- **必须有一个固件 .bin 文件**。该页是「本地固件」模式：点「选择 .bin 文件」自己提供（支持单个合并固件或多个分区 .bin，最多 8 个）。官方 FoloToy AI Passport 固件 .bin 来自 FoloToy（自行用 ESP-IDF 构建，或官方发布包）。**如果你没有 .bin，先别点「开始写入」**——页面不会自动帮你下载固件。
- **浏览器**：必须用 **Chrome 或 Edge（macOS）**，**Safari 不支持 WebSerial**。WorkBuddy 沙箱同样跑不了 WebSerial——必须你真机浏览器操作。
- **USB 线**：用**支持数据传输**的线（充电-only 线刷不了）。

### 操作步骤
1. Mac 上用 Chrome/Edge 打开上面 URL，确认页面显示「当前浏览器可以连接 AI Passport」。
2. 设备用数据 USB 线连 Mac（保持开机）。
3. 点「连接设备」→ 系统弹窗里**选 `USB JTAG/serial debug unit (cu.usbmodem…)`**（macOS 显示 `cu.usbmodem101` 之类）。**不要选**蓝牙/SPP/耳机/`cu.Bluetooth`。
4. 点「选择 .bin 文件」载入你的固件。
5. 波特率建议选 **921600**（最快；不稳再降到 115200）。
6. 点「开始写入」→ 等待进度到 100% → 设备**自动重启**进新固件。
   - ⚠️ 「清除设备数据!」是危险选项，正常刷固件**不要勾**。
   - 若报 `Failed to enter download mode`：ESP32-C3 原生 USB 通常靠 DTR/RTS 自动进下载模式；失败时**按住设备 BOOT(GPIO0) 键再点连接/重连**，松开即开始写。

刷完固件后，回到 §2 跑 `relay.py` 即可（BLE 通道由固件提供）。

## 5. 排错速查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 后台/沙箱里 2s 被杀、前台退出码 134 | CoreBluetooth 被拦 | 必须在真机 Mac 终端跑，给终端蓝牙权限 |
| `未发现设备 AI Passport` | 设备未开机/未广播、蓝牙未授权 | 确认设备开机且处于 BLE 广播；检查蓝牙授权 |
| 转写结果不进输入框 | 未授予辅助功能权限 | 系统设置→隐私→辅助功能，加终端/Python |
| 注入的是原文不是整理稿 | DeepSeek key 错/断网 | 检查 `config.local.json` 的 `deepseek_api_key`；断网时 relay 会回退注入原文 |
| `No module named 'whisper_cpp_python'` | 包名/动态库问题 | 确认 venv 内 `whisper-cpp-python` 已装；macOS 需 `libwhisper.so → libwhisper.dylib` 软链 |
