# AI Passport · 语音整理器

[简体中文](README.md) | [English](README.en.md)

> 一台 ESP32-C3 随身硬件 + 桌面端，把你零碎的口语，变成一段「能直接发出去」的话。

**AI Passport 不是又一个「语音转文字」工具。** 转文字谁都会，它解决的是**最后一公里**——把脑子里那一团口语，理顺成一段"能直接发同事、能直接报领导、能直接派给 AI、能直接贴进文档"的成稿。

---

## 一、先说人话：它解决什么痛点

你一定遇过这些瞬间——

- 脑子里冒出一句要发给同事的话，打开微信却忘了怎么组织；
- 想给领导报个进度，啰嗦半天说不到点子上；
- 脑子里一堆灵感，坐到电脑前全没了；
- 会议纪要、长段口述，转写出来还是一团乱麻，得再手动改一遍。

AI Passport 的逻辑是：**按住说话 → 本地转写（声音不出本机）→ 按你选的场景用 AI 理顺 → 自动填进当前输入框 / 回传手机**。

一句话：把脑子里的碎片想法，用最省力的方式变成一段「能直接发出去」的话。

```text
按住说话 ──► 设备录音 ──► 桌面端中转 ──► 本地 whisper.cpp 转写（音频不出本机）
                    │  经 BLE / USB
                    ▼  识别中 partial 实时
            屏幕预览候选字
                    │
                    ▼  定稿 → 整理层（默认 DeepSeek / 可本地 LLM）按场景整理
            通顺/结构化成稿  ──► 注入当前输入框（仅一次） / 回传手机
```

## 二、四个场景：同一段话，四种成稿形态

设备 HOME 态进入 READY 后先选场景，不同场景对应不同的 AI 整理预设——**同一段口语，整理出来的"样子"完全不同**。下面每个场景都给了「你按着说的」vs「直接发出去的」真实对照。

### ① 同事 · 工作消息
> **什么时候用**：工作群 / 同事消息，想到就说、懒得组织语言。
> **成稿长什么样**：去掉口头禅、补上主语、一句话把事说清。

| 你按着说的（口述） | 直接发出去的（成稿） |
| --- | --- |
| 那个物料清单我发你微信了啊，大概周三到货，你确认一下 | 物料清单已发你微信，预计周三到货，请确认 👌 |
| 海报改了没，改了发我看下呗 | 海报改好了吗？改完发我看一下 |
| 晚上那个会可能要晚十分钟，路上堵 | 今晚会议预计推迟约 10 分钟，路上堵车 |

### ② 领导 / 客户 · 向上汇报
> **什么时候用**：给领导报进度、对客户做沟通，要显得专业、有数。
> **成稿长什么样**：结论先行、书面语、能量化的都量化。

| 你按着说的（口述） | 直接发出去的（成稿） |
| --- | --- |
| 灯光那个器材比预算贵了差不多两万，场地也超了一点，总共超了得有三万吧 | 本期预算超支约 3 万元，主因灯光器材（约 2 万）+ 场地费小幅超支；建议下阶段控灯光采购渠道。 |
| 客户想加个开场视频，我觉得能做，但得加钱排期也紧 | 客户新增开场视频需求，评估可承接；需追加预算并调整排期，请确认。 |
| 系统昨晚上挂了大概半小时，后来重启好了，影响不大 | 昨晚系统故障约 30 分钟，已重启恢复，无业务损失，根因排查中。 |

### ③ 对 AI · 派活指令
> **什么时候用**：给 coding / 工作 agent 派活，口语想法直接变可执行指令。
> **成稿长什么样**：去掉歧义、补上路径/条件，AI 拿到就能干。

| 你按着说的（口述） | 直接发出去的（成稿） |
| --- | --- |
| 帮我把桌面那个 Excel 里重复的行删掉，按金额从大到小排，完了另存一份 | 读取 ~/Desktop/数据.xlsx，删除完全重复的行，按「金额」列降序排序，另存为 数据_去重排序.xlsx |
| 写个脚本每天八点看一眼服务器日志，有 error 就发我微信 | 写 Python 脚本：cron 每天 08:00 抓取服务器日志含 ERROR 的行，有则经企业微信推送给我，附完整代码与部署步骤 |
| 把我这周写的笔记整理成一篇，分成三段，语气轻松点 | 将本周笔记合并为一篇三段式文章（开头/正文/结尾），语气轻松口语，保留全部要点 |

### ④ 语音输入 · 随手记 / 长草稿
> **什么时候用**：灵感、长段口述、写作草稿，不想被打断思路。
> **成稿长什么样**：通顺书面文字，保留全部信息点，不打断你。

| 你按着说的（口述） | 直接发出去的（成稿） |
| --- | --- |
| 今天想的就是产品定位，先打透年轻人这一个人群，别一下铺太开，资源也有限，内容做三个方向，测评、使用场景、吐槽 | 产品定位：聚焦年轻人群，不盲目铺量（资源有限）。内容三方向：①测评 ②使用场景 ③吐槽。先打透单人群再扩展。 |
| 周末想出去玩，近一点的山或者湖都行，别太累，最好能当天回 | 周末短途游：近郊山水类，强度低、当天往返；爬山或湖边二选一。 |

### ⑤ 分段录入 + 合并：碎片也能拼成一篇
> 灵感常是跳着的。分 1–3 段录，每段即时预览，全部录完由整理层去重、理顺、合并成一篇。

- **第 1 段口述**：「下周运营节奏，周一发教程，周三发避坑，周五发幕后」
- **第 2 段口述**：「对了教程那篇标题要想三个备选，避坑的配图用对比图」
- **第 3 段口述**：「还有周更提醒设成周日晚上，别拖到周一」
- **合并成稿**：
  > 下周运营节奏：周一教程（标题备 3 个备选）/ 周三避坑（配对比图）/ 周五幕后。周更提醒设为周日晚上，避免拖到周一。

> 预设把"你的意图"编码进整理——不用每次手写 prompt，选对场景就行。整理层默认走 DeepSeek 云端 API，想进一步把文本也留在本机，可切到本地 LLM（见第四节 / 第八节）。

## 三、它怎么工作（三步，大白话）

1. **录**：READY 态按住「音量+」即开始录音，松开自动发送；音频以 100ms 一帧经 **BLE（蓝牙）或 USB** 任一通道上行。
2. **转**：桌面端把音频送进**本机 whisper.cpp** 转写——说话时屏幕底部就实时出候选字（partial 预览），松手后定稿。
3. **理 + 发**：定稿文本送进**整理层**（默认 DeepSeek 云端 API，也可本地部署 LLM），按当前场景理顺成成稿 → 回显设备屏幕，并**自动注入当前输入框**（剪贴板 + 快捷键，仅注入一次）。

数据流：设备采 16kHz 音频 → 100ms 一帧上行 → 桌面端本地 whisper.cpp 转写 → DeepSeek 按场景预设理顺 → 成稿回显 + 注入输入框（或回传手机）。Agent 状态、审批请求与按键裁决走反向通道。

## 四、为什么是它：六大优势

| 优势 | 技术事实 | 对你意味着什么 |
| --- | --- | --- |
| **🔒 隐私优先，全程可不出本机** | ASR 跑在本机 whisper.cpp，零云端费用；整理层默认走 DeepSeek API，但**可本地部署**任意 OpenAI 兼容 LLM（Ollama / llama.cpp / LM Studio 等）——从麦克风到成稿**全程不出本机** | 敏感内容（含说话文本）彻底不上传任何云端，隐私由你掌控；嫌配本地模型麻烦时，默认 API 也只发中文文本、绝不出声音 |
| **🎯 场景化整理** | 同一段口语按「同事 / 领导客户 / 对 AI / 语音输入」四种预设整理成不同形态 | 不用自己琢磨"这话该怎么说"，选场景自动成型 |
| **🧩 分段录入 + 跨段合并** | 1–3 段分别录制，每段即时预览，全部录完由 DeepSeek 去重、理顺、合并成一篇 | 灵感是碎的、跳的也没关系，拼起来就是完整稿 |
| **⚡ 连续快录** | 「语音输入」场景松手即回就绪态，可立刻录下一句（v0.2.4） | 灵感连续迸发时一口气记，不用等上一段整理完 |
| **🔗 双通道冗余链路** | 一套协议跑 BLE（GATT `0xA2B0`）+ USB-Serial-JTAG 两条物理通道，任一断线自动收束回 READY | 蓝牙断了插线接着用，链路故障不会废掉设备 |
| **✋ 物理安全审批** | Agent 的权限请求不是通知，而是设备屏幕上的审批页——OK 批准 / UP 拒绝，实体键才算数 | AI 要执行危险操作（改文件、跑命令），得你亲手按键才算数 |

> 另含**两级超低功耗**（20s 无操作关背光、60s 面板断电进 μA 级睡眠，任意键瞬时唤醒）、**实时候选字预览**、**悬浮窗不抢焦点**（按住说话不卡桌面）等细节体验。

## 五、功能清单

### 设备端（固件 · ESP32-C3）

- **按住说话**：READY 态按住「音量+」即录（滴声提示），松手自动发送；短于 500ms 误碰当场丢弃
- **场景选择**：HOME → READY 后在「同事 / 领导客户 / 对 AI / 语音输入」间用 UP/DOWN 选、OK 确认，场景标签显示在就绪页顶栏
- **分段录入（①–③）**：最多 3 段，每段定稿即时预览，OK 结束 → 合并页看 DeepSeek 成稿 → OK 注入 / 放弃
- **连续快录（④）**：松手即回就绪态，可立刻录下一句；各段成稿在桌面端按序累计
- **转写中退出**：TRANSCRIBING 态单击「音量+」立即退出，迟到的识别文本不上屏
- **真锁屏**：锁屏态任何键都不亮屏（省电），仅 OK 长按解锁
- **Agent 工作流可视化**：THINKING / RUNNING / DONE 状态、任务回显、离线横幅
- **物理审批**：审批页 OK 批准 / UP 拒绝 / DOWN 看 Diff 详情，审批态屏幕常亮
- **三键交互**：UP/DOWN/OK —— 按住说话、转写中单击退出、单击回车、长按清空输入框
- **完整状态机**：HOME → READY → LISTENING → TRANSCRIBING → SCENE_SELECT → SEG_WAIT → MERGE_REVIEW → AGENT_RUNNING → APPROVAL → DONE
- **双通道传输**：BLE / USB-Serial-JTAG（含完整控制台命令面）
- **两级息屏**：20s 关背光 / 60s 面板 SLPIN 断电 / 任意键唤醒
- **控制台命令**：`st`（状态）、`log`（日志环）、`rst`（复位原因）、`time`（校时）、`bt scan/dtx`（射频诊断）、`reboot`、`factory`（清 NVS）

### 桌面端（companion/ · macOS + Windows）

- **本地 whisper.cpp ASR**：替代上游火山云端 ASR，转写在本机完成，零云端费用、音频不出本机；接口对齐上游 `asr_client.StreamingASR`，relay 一行即可切回云端后端
- **DeepSeek 整理层**：`refine_deepseek.py` 在定稿后、注入前按场景预设理顺；**默认调用 DeepSeek 云端 API，可切换为本地 LLM**（OpenAI 兼容端点，如本机 Ollama / llama.cpp），实现文本也不出本机；网络 / 密钥 / 本地模型均失败时**回退注入原文**，保证"最差也能用"
- **候选字悬浮窗**：ASR 中间结果实时显示在屏幕底部居中无边框置顶小窗，自动换行、随内容生长；松手后整理成稿注入一次、窗口消失
- **不抢焦点**：悬浮窗绝不 focus；Windows 走 `WS_EX_NOACTIVATE`、macOS 热路径不触发 WindowServer 同步（按住说话不卡桌面）
- **高频帧合并**：120ms 合并窗口只刷最新帧，首帧立即渲染，杜绝逐帧重绘卡顿
- **5 步向导**：欢迎 → 自动发现设备（BLE → USB）→ 本地模型/整理配置 → 系统授权引导（macOS）→ 完成状态页
- **托盘驻留**：连接后驻留系统菜单栏/托盘，状态行 + 诊断 + 设置
- **诊断页**：USB 通道完整设备命令面；BLE 通道只读运行状态
- **注入**：macOS 剪贴板 + Cmd+V（需辅助功能授权；中文必须走剪贴板通道）；Windows 独立注入器

## 六、与上游 FoloToy AI Passport 的区别

本项目基于 [FoloToy AI Passport](https://github.com/zhaohuaxiaoy/folo-ai-passport-voice)（MIT）二次开发，底层框架（ESP32-C3 固件状态机、LVGL UI、BLE/USB 双通道、物理审批）继承自上游，在此之上做了场景化与本地化改造：

| 维度 | 上游 FoloToy AI Passport | 本 fork（AI Passport 语音整理器） |
| --- | --- | --- |
| **定位** | 通用语音输入 + AI Agent 控制面 | 场景化「语音 → 可发送工作信息」整理器 |
| **ASR** | 火山引擎云端流式 ASR（需密钥、音频出网） | **本地 whisper.cpp**（零云端费用、音频不出本机） |
| **智能层** | Agent 思考 / 执行 / 审批可视化 | **DeepSeek 按场景**把口语理顺成成稿（可本地部署 LLM，文本亦不出本机） |
| **录入方式** | 单段按住说话 | **1–3 段分段录入 + 合并**、连续快录（v0.2.4） |
| **整理形态** | 原样转写文本 | 按场景转写成消息 / 汇报 / 指令 / 文字 |
| **回传** | 注入桌面输入框 | 桌面注入 + 企业微信回传（设计中） |
| **共用底座** | 双通道 / 状态机 / 物理审批 / LVGL | 沿用并扩展 |

## 七、架构总览（开发者）

| 层 | 组件 | 职责 |
| --- | --- | --- |
| 设备端 | ESP32-C3 固件（ESP-IDF 5.5 + LVGL 9.5） | 状态机、按键/录音、场景选择、UI 渲染、双通道传输、功耗管理 |
| 桌面端 | companion（macOS / Windows） | 双通道接入、本地 whisper.cpp ASR、DeepSeek 整理层、悬浮窗、剪贴板注入、向导、托盘 |
| 本地模型 | whisper.cpp（ASR，本机）+ 整理 LLM（默认 DeepSeek V4-Flash API，可本地部署 Ollama / llama.cpp） | 音频 → 文本（本机）；口语 → 场景化成稿（API 或本地 LLM，本地部署时文本亦不出本机） |

> 设计上：核心状态机是纯 C 归约器（`state + event → action`），零 ESP-IDF 依赖，host 测试直接跑在 PC 上；UI 按快照差异渲染，逻辑与硬件彻底解耦、可单测、可移植。在仅 400KB SRAM 的 ESP32-C3 上以 3200B/100ms 帧流式上行——静态环形缓冲零动态分配、源端丢帧不整段缓存、掉帧对账防静默丢失。

## 八、快速开始（开发者）

### 桌面端（Mac / Windows）

**系统要求**：

| 平台 | 系统版本 | 架构 | 说明 |
| --- | --- | --- | --- |
| macOS | 11.0（Big Sur）及以上 | **Apple Silicon（arm64）** | Intel Mac 暂不提供官方产物（Pillow 无通用二进制，需 x86 环境自构建） |
| Windows | 10 1803+（建议 21H2）/ 11 | x64 | bleak winrt 后端要求；首次运行需允许防火墙 |

**配置本地模型与整理后端**（默认本地 whisper.cpp + DeepSeek V4-Flash）：

1. 准备本地 whisper 模型（见 `companion/install_whisper_local.sh` 与 `asr_local_whisper.py` 注释）
2. 在 `companion/config.local.json` 填入 DeepSeek Key（`deepseek_api_key`，或导出 `DEEPSEEK_API_KEY`）与 `refine_preset`（默认 `work_wechat`）
3. 首次运行自动生成 `companion/config.local.json`（**不入 git**）

> **整理后端可本地化（全面隐私）**：默认 `refine_deepseek.py` 走 DeepSeek 云端 API（仅发中文文本）。若你对隐私要求极高，把整理端点切到本机 LLM 即可让**口语文本也不出本机**——将 `refine_backend` 设为本地 OpenAI 兼容端点（如 Ollama `http://localhost:11434/v1`、或 llama.cpp / LM Studio 暴露的 `v1`），并留空 `deepseek_api_key`。从麦克风采集到成稿注入，整条链路落在你自己的机器上。
> **可选云端 ASR 后端**：上游火山引擎云端 ASR 仍可通过把 `from asr_local_whisper import ...` 换回 `from asr_client import StreamingASR` 启用，适合无本地算力的机器（注意音频会出网）。
> **安全**：API Key 只存于 `config.local.json`（已 .gitignore）或向导本地配置，**严禁提交进 git**；泄露可在控制台随时吊销重建。本地部署模式下无需任何云端密钥。

**从源码运行（开发）**：

```bash
pip install -r companion/requirements.txt
cp companion/config.example.json companion/config.local.json   # 填入 DeepSeek Key 与整理预设
companion/.venv/bin/python companion/fre_app.py                 # 向导 GUI（--dry-run 假链路演练）
companion/.venv/bin/python companion/relay.py                   # CLI 中转（BLE 自动扫描 "AI Passport"）
```

macOS 首次使用需授予**辅助功能**权限（注入剪贴板+Cmd+V 必需）与蓝牙权限。Windows 使用说明见 [`companion/WINDOWS.md`](companion/WINDOWS.md)。

### 固件（ESP32-C3）

需要 ESP-IDF 5.5.x（已知环境 5.5.3）+ Python 3.10+（本机 `.venv` 在 `companion/`）。

**首次构建**（会经 Component Manager 拉取 LVGL、`esp_lvgl_port`、`button`、`esp_codec_dev` 等依赖）：

```bash
git clone <repo-url> && cd ai-passport
python3 -m venv companion/.venv && companion/.venv/bin/pip install -r companion/requirements.txt
source "$HOME/esp/esp-idf-v5.5.3/export.sh"   # 或你的安装路径
idf.py set-target esp32c3
idf.py build
```

**刷机与日志**（设备用 USB 线连电脑，`/dev/cu.usbmodem*` 按实际端口替换）：


## 十、设计决策（为什么这么做）

- **为什么本地 ASR + 可本地整理**：隐私与成本是硬约束——语音是高度敏感数据，本地 whisper.cpp 让音频从不出网、零按量费用。整理层默认走 DeepSeek API（仅发中文文本），但**支持本地部署 LLM**：当用户对隐私要求极高时，可把整理端点切到本机 Ollama / llama.cpp，实现从麦克风到成稿**全流程不出本机**；网络/密钥/本地模型失败时仍可回退原文。
- **为什么场景化整理**：用户要的不是"我说了什么"，而是"这段话发出去该长什么样"。同事消息要简洁、对领导要结论先行、给 AI 要可执行指令、随手记要通顺文字——预设把"意图"编码进整理，避免每次手写 prompt。
- **为什么分段录入 + 合并**：灵感常是碎片、跳跃、跨多次口述的；逐段预览 + 跨段去重合并，比单次长录更易控、成稿更连贯。
- **为什么双通道**：BLE 覆盖有蓝牙的 Mac；USB 是调试器兼最后保底——任何单一链路失效都可用另一条继续工作，断线事件统一收束，不残留半开会话。
- **为什么状态机是纯 C 归约器**：`state + event → action` 的归约模式让全部转移逻辑零硬件依赖，host 侧测试直接覆盖状态转移、协议编解码、音频分片、UI 像素计算；UI 按快照差异渲染，加页面不加状态耦合。
- **为什么音频管线做静态环形缓冲**：ESP32-C3 只有 400KB SRAM，动态分配 + 整段缓存一次长录音会直接爆内存。3200B/100ms 帧、源端丢帧、掉帧对账，是"入门级 MCU 也能当 AI 输入设备"的关键。
- **为什么物理审批**：AI 自动改文件、执行命令是有风险的——审批不放通知栏，放设备屏幕，按实体键才算数，且审批态永不熄屏。

## 十一、真机验收 / 路线

**真机验收状态**：设备到货后的完整验收清单见 [`docs/ON_DEVICE.md`](docs/ON_DEVICE.md)。当前状态：**Build PASS、Host tests PASS、真机连续实测 PASS**。已真机验证：四场景切换、1–3 段分段录入与合并、连续快录、按住说话多次会话、连续快速长按无丢键、转写中单击退出、双通道传输、休眠唤醒、真锁屏。仍待重点验收：Windows 焦点不抢占、长句连续十几秒无丢字、USB 拔线恢复、电池读数、企业微信回传。

**路线 / 设计中**：

- **企业微信回传**：把整理成稿经企业微信 push 回手机（规避个人微信封号风险），让"语音录入 → 手机可取"闭环——桌面注入已实现，手机回传为下一步。
- **多段编排状态机**：逐段预览 + 确认后统一整理，支持更长的连续口述。
- **像素风 UI**：在 240×320 屏上用索引色小图（≤128×128）呈现物品/人物形象，资源占用低（~50–200KB Flash、几乎零 RAM）。
